# 如何研究回溯性重构（框架）

> **回溯性重构不是「先立结论再找证据」，是「先有走过的路，再回头把逻辑写清楚」。**
> 这份是研究方法的骨架——给做这件事的人，也给接手的 AI。

## 一、这个框架要回答什么

**一个判断，是怎么从「当时以为对」变成「现在知道它缺了哪块」的。**

不是问「这对不对」，是问三个问题：

1. **它当时为什么看起来对？**（自洽性——缺块没进场，所以看起来完整）
2. **学错了什么才让它塌？**（推翻了哪一块「曾经的正确」）
3. **这个过程能复现吗？**（下次遇到同类，能不能提前自查）

## 二、方法：把「判断」那一步拆开

回溯性重构的核心动作是**拆「判断」**——一个判断不是一个结论，是**三步**：

```
当前正确的（正） —— 此刻对的，先认下来
        │
        ├─ 曾经（反） —— 曾经正确过、后来失败了的
        │     ├─ 单一归因：只揪一条变量，错得清楚，知道反例在哪
        │     └─ 归因不全：真的以为全了、其实缺一块 —— 更致命
        │
        └─ 猜测（中） —— 还没验的，分离单一变量、做对照
```

**拆开后每一格都是参考，不是判决。** 正反各自得出不一样的结果，**中间是常态**。

## 三、研究的动作顺序

1. **留过程，不是留头尾**——中间怎么想、试了什么、哪步开始不对。过程才是能被学的。
2. **一例一档**——反例是「过程中的错误」；真正结果要**一一对照**（错在过程哪一步 → 后来真实结果）。
3. **看出缺哪块**——归因不全要专门验证：不是问「哪条错了」，是问「当时为什么以为它对」。
4. **猜的标「中」，不急着标「正」**——分离单一变量、对照，**验了才移走**（对了去 `正\复现经验\`，塌了去 `反\`）。
5. **推翻的东西不删**——留下「曾经对、后来塌」的原样，那是「曾经」本身。

## 四、两条纪律

- **学习即推翻**：任何池子都不完全——**被推翻的不是错的，是曾经对的**。找的是**过程错在哪**。
- **逻辑变更即证实**：框架自己也会被推翻（比如「中间=未判断」已经被改成「中间=猜测」）——**每一次修正都是这个框架的实证**，不是失败。

## 五、怎么判断研究有进展

- **反例能一一对照**（不是只记结论）
- **归因不全的清单在变长**（说明开始看见「没进过场的缺块」）
- **正来自反**（每条复现经验能说清它从哪个「曾经」里长出来）
- **猜测能验**（中→正/反的迁移在发生）
